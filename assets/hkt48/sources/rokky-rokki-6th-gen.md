# ロッキー / ろっきー = HKT48 6th gen

**Verdict: LOCKED for this glossary.** In HKT photo/greeting and member-talk context, **ロッキー／ろっきー** is the collective shorthand for HKT48's **6th generation (六期生)**, not a member's personal name “Rocky.” It is the same kind of generation shorthand as the existing **ななき／七期** entry for 7th gen.

## Evidence

- **Member talk (RKB/HKT podcast):** [＃062 いぶれいあの声のバレンタイン](https://listen.style/p/hkt48/qctcuotf) identifies the speakers as 6th-/5th-generation HKT members in the episode metadata and repeatedly says **ロッキー** while discussing 最上奈那華 and her同期; the phrase “ロッキーの年長者” and “ロッキー全員” clearly refer to the cohort, not an individual. This is direct member-talk evidence, not ASR.
- **Fan report quoting the official announcement:** [HKT48いもまと, 「希望のつぼみ」リバイバル公演](https://asukyann.blog.jp/archives/90486007.html) reproduces the official notice for a “HKT48 6期生” revival and contemporaneous fan comments use **ロッキー** for that same 6th-gen group.
- **Official roster context:** [HKT48 official 7th-gen X announcement](https://www.hkt48.jp/news/2024/08/9924) labels the next cohort **7期生**; the official grouping/roster contains no member named Nanaki. The local glossary's existing user-verified **ななき／七期** lock therefore remains consistent as a collective 7th-gen shorthand, not a personal name.

## subtitler lock

- JA: **ロッキー／ろっきー**, underlying **六期／六期生／6期生**.
- ASS EN **always**: **6th gen** / **6th gens** (user lock 2026-09-30). Pattern for all gen slang: **Nth gen(s)** — never leave **Rokky / Rokki / Nanaki** in ASS (EN speakers won’t understand the in-group label).
- Reject: **Rocky** as an individual member/name; **Rocky Balboa**; any mapping to a specific member; **Rokky pose** → **6th gen pose**.
- Confirm existing companion: **ななき／七期 = 7th gen**; keep `nanaki-7th-gen` consistent (ASS EN **7th gen**, not Nanaki).

The public indexing for the spelling **ななき** is thinner than for ロッキー, so this note does not use the 7th-gen roster alone as independent proof of that spoken variant; it preserves the existing user-verified lock rather than inventing a new one.
